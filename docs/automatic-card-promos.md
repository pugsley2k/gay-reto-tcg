# Automatic promos and TikTok inbox approval

New available listings create an immutable video job for their listing revision. The shop PC polls every minute and uses the existing catalogue artwork/logo animation to render a silent 1080 × 1920 H.264 MP4. Rendering uses headless Edge and local FFmpeg; it does not require Seller Studio to be open. The PC must be awake and signed in. Its per-user Windows task is `GayRetroTCG-CardPromoWorker`, runs without administrator rights and opens no visible terminal. It restarts at sign-in. Disable it in Seller Studio to stop new work, or stop/remove that named task in Windows Task Scheduler.

Open Seller Studio → Agent control centre → Automatic card promos. Wait for **Waiting for your approval**, choose **Review video**, check the video and caption, verify the connected TikTok account, tick the consent checkbox, then choose **Approve & send to TikTok inbox**. The initial owner-supplied account label is `@aitogethertm`. That is a label, not a profile name verified through TikTok: the existing authorization only has `video.upload`. Changing the underlying account clears its label and blocks approvals bound to the old account.

TikTok inbox delivery is not a public post. Open TikTok's inbox notification to finish editing and publishing, paste the caption from Seller Studio, and choose music there if desired. There is no paid advertising or Direct Post integration. TikTok's [Direct Post requirements](https://developers.tiktok.com/docs/en/content-sharing-guidelines) require `video.publish` and an audited public-facing integration; its intended-use rules exclude private own-account uploader tools. Do not bypass these limits or silently request wider permissions. The workflow reuses the existing TikTok authorization/refresh adapter only; it does not invoke Suno music generation, lyric syncing or its schedule.

Videos are held in the private Supabase `card-promo-videos` bucket. Preview links expire after five minutes. No anonymous bucket reads are granted. Maximum video size is 3.5 MB, up to 10 successful previews per day and 30 retained previews. Reaching the cap pauses new renders, rather than buying capacity. Existing platform quotas still apply; no plan, paid renderer or subscription is enabled. At the retention cap, ask for an archive/cleanup of old previews before adding capacity.

The local worker has a random scoped bearer key, encrypted with Windows DPAPI for the current user. Only its SHA-256 hash is stored in `promo_workers`. It cannot edit cards, orders, checkout, metadata or payment data. TikTok credentials remain in the existing local credential store and are never returned to Seller Studio or copied into hosting configuration. Local private configuration, temporary files and recovery ledgers live in the Git-ignored `.promo-worker` directory. Do not print or commit its decrypted credential.

Render jobs use expiring, fenced leases and bounded crash retries. Price, availability and revision are checked before rendering, before accepting the finished file and immediately before an upload attempt. Checkout-held cards block processing. Owner approval binds the rendered checksum, caption, account hash and listing revision for 30 minutes. A video cannot be uploaded without a recorded approval. The worker checks the checksum after downloading and verifies the actual token's account again immediately before use.

Upload initialization is never blindly retried. The local ledger records an attempt before the provider request and saves TikTok's publish ID before sending video bytes. If a response is lost, later polls recover that existing provider reference. Uncertain uploads without a reference require manual review; there is no resend button for uncertainty. Inbox delivery, processing, failure and uncertainty are shown separately. Cancel affects only approvals that have not been claimed. Changing a listing cannot recall an already-delivered video, so verify availability before completing an old inbox post.

Installation: apply `20261018211252_automatic_card_promos.sql` before deploying. `scripts/promo-worker-secret.ps1 -Initialize` writes a DPAPI credential and returns only a worker ID and token hash; register those in the private worker table. Then `scripts/install-promo-worker.ps1` installs and starts the per-user task. Dependencies are the repository's development packages, installed Edge, Node, FFmpeg and FFprobe. Existing local Codex runtime packages can supply Playwright on this PC. No new OAuth app or port listener is required.

Validation: library tests; checkout and promo PostgreSQL/PGlite suites; `node --test tests/promo-worker.test.cjs`; `npm run test:promos:browser`; production build; one live automatic render and owner preview. Upload tests mock TikTok and verify provider-reference persistence and duplicate suppression. No live upload is performed as an installation test. Public posting cannot be claimed as tested.
