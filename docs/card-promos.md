# Card promo studio

The default workflow now prepares finished videos on the shop PC and offers owner-approved TikTok inbox delivery. See [Automatic promos](automatic-card-promos.md). The controls described below remain available under **Manual video preview and export tools**.

Open Seller Studio → Agent control centre → Card promo studio. Available listings automatically join a private database queue when added. The existing available stock is included on installation. A price, artwork, condition or availability change refreshes the draft revision. This is event-driven and does not wait for the daily agents.

Choose **Preview promo**, optionally change the colour treatment, then **Play preview** or **Export MP4**. Keep the tab visible for eight seconds. Download the MP4 and copy the caption. Upload it to TikTok and choose music there. Nothing is sent or posted by the studio; no Suno dependency, account credentials, paid model, cloud renderer, new scheduler or video storage is used. The browser produces a silent H.264 MP4, 1080 × 1920, approximately eight seconds. Current Chrome/Edge with MP4 MediaRecorder support are recommended. Unsupported browsers get an explicit message rather than a mislabeled WebM file.

The clean catalogue card artwork is used, never uploaded photos. The existing catalogue lookup now retains matching artwork for graded cards, while condition evidence stays in `front_image_url` and `back_image_url`. If TCGdex lacks artwork, an English card may use Pokémon TCG API artwork only after matching its identifier, name, number and set. Edition-sensitive images remain subject to existing restrictions. There is no guessed or generated artwork. A missing match blocks the promo and asks for a catalogue refresh in Manage cards.

The homepage, shop and sale page show catalogue artwork, with a placeholder if none is available. On the sale page **View photos** reveals the actual front/back photographs; they are not requested as images before that click. Artwork is labelled as reference and grading/condition remain visible. Photo URLs remain public listing data; this is a display change, not private photo storage.

The private queue has RLS and no anonymous/authenticated access. Admin routes enforce the Clerk admin role and same-origin decisions. Artwork downloads proxy only strict catalogue image URLs, reject redirects and cap bytes/time. Availability, current revision and active payment holds are checked before rendering and again before offering the download. Sold, hidden and checkout-held cards cannot export. Previously downloaded videos cannot be recalled: check stock and price again before posting an old file. An exported status means an MP4 was prepared, not uploaded or published.

Install `20261018204942_card_promo_queue.sql` before releasing. It adds the queue, a listing-change trigger and service-only functions without altering checkout functions. All functions are security invoker with an empty search path. The trigger performs no network or rendering work.

Verification: `node --import tsx --test src/lib/*.test.ts`, `node --test tests/checkout-database.test.mjs tests/card-promo-database.test.mjs`, `npm run test:promos:browser`, `npm run build`. Browser tests bundle the actual studio and product components into an isolated local harness, mock admin requests and never post or charge. Optional `PROMO_TEST_ARTWORK` supplies a local artwork proof file; otherwise a bundled fixture image is used. `PROMO_TEST_VIDEO`, `PROMO_TEST_SCREENSHOT` and `PROMO_TEST_MOBILE_SCREENSHOT` save review artifacts. The normal checkout browser suite still runs against a local production server.
